# 照片增量备份

![应用图标](Resources/AppIcon-256.png)

这是一个本机运行的 macOS 应用，通过 Apple PhotoKit 读取系统照片图库，将照片和视频资源复制到指定目录。无需 Apple 账户密码，也不调用外部 AI 服务。

适用于 Apple 芯片 Mac，要求 macOS 13 或以上版本。提供菜单栏常驻、增量复制、实况照片资源保留、历史版本及源图库删除后的可恢复归档。

**下载安装包：[最新 Release](https://github.com/SamonCloud/icloud-photo-backup/releases/latest)**。下载其中名称以 `AppleSilicon.dmg` 结尾的安装包，打开后将应用拖入 Applications。镜像内包含中文安装说明。

发行版目前为本地临时签名，尚无 Developer ID 签名和 Apple 公证；首次打开受到系统拦截时，按镜像中的说明处理。请从本仓库 Release 下载，并使用同时提供的 SHA-256 文件核对完整性。

## 使用方法

1. 双击 `dist/照片增量备份.app`。
2. 点击“选择目录”，选择移动硬盘或已在访达中挂载的 NAS 上的专用文件夹。建议新建“照片备份”文件夹，不要选择 Apple 照片图库内部。
3. 点击“开始增量备份”。macOS 首次询问照片访问权限时，允许访问全部照片。虽然系统权限名称可能包含“读写”，本应用仅调用读取、导出接口，不调用图库修改接口。
4. 保持“以后每次打开应用时，自动开始增量备份”选中。之后每次启动，应用都会检查当前图库，只补充尚未完成备份的资源。也可以不关闭应用，手动再次点击开始。
5. 默认启用“必要时从 iCloud 获取原片”。应用先尝试本地读取，只有系统明确返回需要联网（3164）时才允许 PhotoKit 联网重试。可关闭此选项，坚持仅备份本地可读资源。
6. 可以先点击“试运行前 5 项”，验证真实目标的读写。试运行会实际备份前 5 个图库项目，不代表全部图库已检查；之后完整运行会跳过已完成资源。
7. 查看完成结果和失败数量。失败资源不计入已备份，下次会重试。点击“查看本次日志”可查原因。两个标签页均提供“打开上次任务日志”：重启应用后仍可查看最近任务；任务执行期间打开前一次任务的日志，任务结束后打开刚完成的日志。没有历史日志时按钮不可用。

应用在启动时运行一轮，不是常驻监听，也不会在退出后继续运行。目标未挂载时会停止，不会在原挂载路径创建替代目录。通过访达重新连接后，可点击开始重试。更换目标文件夹后，该目录独立建立备份记录；没有本应用记录的已有文件不能直接视为已备份。

## 相机导入（1.4.0）

在第三个标签页选择存储卡卷和已连接的导入目标。会遍历卡内所有相机目录（含隐藏目录；排除 .Trashes、.Spotlight-V100 等系统服务目录及 AppleDouble 元数据），不跟随符号链接；只读取卡内文件，不删除或改动存储卡。可识别 JPG/JPEG、HEIF/HEIC/HIF、TIFF 等图片，ARW/DNG/CR2/CR3/NEF/RAF/ORF/RW2 等 RAW，以及 MP4/MOV/MTS/M2TS/MXF/AVI 等常见视频；不导入 XML 等非媒体边车文件。

- 日期规则默认为 `yyyymmdd`，`mm` 表示月份，也支持 `yyyy-mm-dd_旅行`、`yyyy年MM月dd日` 等包含年、月、日的命名；不能包含路径分隔符。普通图片和视频放入日期目录，RAW 放入其 `RAW` 子目录。
- 日期优先读取照片及系统能解析的 RAW 的 EXIF 拍摄日期，以及视频带明确时区的创建日期。没有可靠拍摄日期时使用文件修改日期（旧相机只有通用视频时间头、没有明确时区的情况也使用文件修改日期）。无时区的 EXIF 和日期目录按 Mac 当前时区解释；不支持解析的 RAW 仍原样复制，日期使用回退规则。
- “只导入新文件”默认开启并记住选择。在目标 `.camera-import` 下按存储卡卷标识保存成功记录，记录相对来源、文件大小、修改时间、拍摄日期、目标路径和内容哈希；另存最近成功拍摄文件。使用逐文件记录而非仅按最后文件名或时间截断，避免卡内编号重置、同一时间 JPG/RAW 配对或较早失败项被漏掉。已成功记录且目标普通文件仍存在、大小一致时跳过；目标缺失、失败、停止和用户跳过的文件仍可重试。目标同大小内容被外部替换时不会自动发现，可关闭开关重新核对。
- 对尚待导入的日期，在目标直接子目录中检查日期前缀。例如 `20261101`、`20261101_旅行` 都会提示；自定义规则也按其日期部分前缀识别。选择“跳过”会跳过此日期所有待导入的图片、RAW 和视频；“全部跳过”对本次其他已存在日期同样生效，新日期仍导入。也可“继续导入”或“停止导入”。选择仅本次有效，跳过不写成成功记录。
- “继续导入”使用规则生成的目录，不自动合并到任意已有日期后缀目录。最终同名文件内容相同则复用，不同则以 `_2`、`_3` 等名称保留两份，不覆盖原文件。文件先写临时文件，完成后发布并持久记录；停止时未完成文件下次重新传输，已成功文件不重复导入。
- 显示扫描、导入／跳过／失败数量及估算剩余时间，提供“打开上次任务日志”；日志保存在本机 `~/Library/Application Support/PhotoIncrementalBackup/CameraLogs/`，任务结果重启后仍可见。关闭窗口继续导入，退出时先请求停止；不会导入完成后自动退出。相机导入与其他两页任务互斥，防止目标写入冲突。

## 目录复制（1.3.0）

窗口分为两个标签页：“照片备份”保留原有功能，“目录复制”用于普通目录之间的复制，不需要照片访问权限。先选择两个已连接的目录，点击“开始 / 继续复制”；复制的是源目录内的内容，不在目标中额外套一层源文件夹名。

- 默认开启“快速检查”，并记住开关选择。每个目录分别比较直属普通文件的数量与总字节数，一致就跳过这些文件的名称和时间检查，子目录独立检查；不按整棵目录树汇总，以免父目录的总量相同掩盖子目录变化。首次运行及停止后恢复都适用。统计仍需枚举文件并读取大小，无法免去网络目录读取，主要减少 NAS 上逐项读取时间及核对名称的请求。相同数量和总大小可能掩盖等大小替换、重命名、时间变化；需要完整检查时关闭此开关。包含符号链接或无法统计的目录回到逐项检查；选择不保留目标独有文件时，名称集合变化也会回到逐项检查，避免先归档旧名称却漏复制新名称。
- 关闭快速检查，或目录统计不一致时，完整检查源、目标差异。1.3.2 起只要求同一相对路径下的文件名、文件大小、创建时间和修改时间一致，时间仅比较 Unix 秒值，不比较纳秒。权限、所有者／组、文件标志、扩展属性和 ACL 不参与跳过或成功判定，也不为读取这些可选属性增加扫描开销。文件类型及符号链接目标仍用于基本安全检查；默认不对符合四项条件的文件逐字节核对内容。
- 同名且四项条件不一致的文件先复制到临时文件，完成数据和时间设置后替换目标，再核对文件名、大小和秒级时间。其他元数据仍通过系统接口尽量复制，无法保留时仅记录提示。真正的读写失败、文件／目录类型冲突和秒级时间不一致仍报错，日志列明相关大小与时间值，不递归删除目标同名目录。
- “包含隐藏目录”默认关闭，排除点号命名及 Finder 隐藏标志的目录与其子项；隐藏文件仍复制。符号链接作为链接复制，不跟随遍历；目标父路径包含符号链接时拒绝写入，避免写到所选目标以外。
- “保留目标独有的文件”默认开启。关闭后，文件及目录属性检查成功且源目录结构稳定时，将目标独有项移入 `.directory-copy-archive/<批次>/files/`，保留目录结构和批次清单，可手动恢复；不永久删除。被排除的隐藏目录及应用自身工作／归档目录不参与清理。
- 中断后重新点击开始仍会扫描差异，但已完成且属性一致的文件不再传输。未完成文件保存在目标 `.directory-copy-<任务标识>` 中，下次核对源属性与已传片段，从断点继续；片段损坏时只重传这个文件。完成后清理本任务的空工作目录，不递归删除未知内容。
- 1.3.5 起逐块释放读写与断点片段校验的临时缓冲区，避免长任务累计占用内存；文件哈希计算也逐块释放。检查及复制全程保持防闲置睡眠。任务状态随进度约每 5 秒保存一次，完成、停止和失败时立即保存；重启时显示上次结果，运行中被终止则提示未记录完成。旧版日志没有完成记录时提示核实，不假定成功。完成后应用继续运行，不自动退出。
- 界面显示扫描状态、文件数、跳过数、失败数、数据量及预计剩余时间。预计时间依据本轮实际传输速率估算，排除复用的旧片段；扫描期间、尚无足够数据时显示“正在估算”。网络速率和磁盘状态变化会影响估计，不包含后续不可预测的属性处理耗时。
- 两个标签页可以处理互不重叠的目录；任务目录相互重叠时阻止并发操作。关闭窗口继续工作，退出应用前需要停止正在进行的任务。目录复制的路径和选项会记住，但不随应用启动自动执行。

其他属性能否完整保留受目标文件系统、NAS 服务端和当前用户权限限制，差异不会导致重复复制。inode、ctime 等由目标系统重新生成，硬链接当前按普通文件独立复制，磁盘占用布局不保证一致。断点恢复仍按源文件的高精度时间和已传内容校验，避免误用变化后的源文件片段。目录复制日志位于 `~/Library/Application Support/PhotoIncrementalBackup/CopyLogs/`。

## 照片备份常驻方式

1.0.2 起，启动后在屏幕顶部菜单栏保留照片图标，备份进行时显示检查进度百分比。点击图标可以查看检查项目数、复制和失败数量，也可以开始、停止备份，或打开主窗口和目标目录。

点击主窗口左上角关闭按钮只隐藏窗口，正在进行的备份会继续。1.3.1 起，应用同时在程序坞（Dock）和菜单栏显示；点击程序坞图标可重新打开窗口。需要完全退出时，使用菜单栏中的“退出照片增量备份…”。备份中退出会先请求停止，待当前文件结束后，再次点击退出即可。菜单栏常驻本身不会开启定时备份，也不会改变“启动时自动备份”的已有设置。

## 备份内容和增量规则

- 读取的是 macOS 的“系统照片图库”，不是某个指定 Apple 账户的远端接口；如果系统图库中还有手动导入的照片，也会备份。其他独立图库需先在“照片”中正确设置为系统图库。它不是照片图库数据库的完整备份，不能恢复相簿组织、人物识别结果等信息。
- 备份照片、视频及 PhotoKit 为其返回的全部资源，包括实况照片的图片和配对视频、可访问的 RAW 和编辑相关资源。资源保留原有编码，不转换为 JPEG。不同资源单独计数，数量可能多于“照片”App 的项目数。
- 请求包含隐藏照片和连拍中的全部可访问项目；“最近删除”、仅在共享相簿中的内容、未获权限的内容不属于完整保证范围。共享图库的可见范围由 Apple PhotoKit 和账户状态决定。
- 默认优先读取本地资源。对于 PhotoKit 返回的 `PHPhotosErrorDomain / 3164`（networkAccessRequired），若“必要时从 iCloud 获取原片”已开启，则联网重试一次并显示进度；联网失败仍记录为失败，不会标记为已备份。关闭该选项后，需在“照片”中完成下载再重试。该错误表示当前资源请求需要网络，不能单凭这一错误判定整个图库未同步。
- 以图库项目标识、修改版本、资源类型和文件名识别资源。已完成且目标文件大小正常时跳过；修改时间变化后重新导出核对 SHA-256，内容相同则复用已有文件，只有内容变化才把旧副本移入 `_versions`。图库重建、迁移后标识变化，也可能重新复制。
- 每个新文件先写到目标磁盘上的临时文件，PhotoKit 成功返回后计算 SHA-256，再移动到最终位置并持久化记录。中断后，下次会清理临时文件并继续。发生同路径内容冲突时保留旧文件，另存新文件；不会覆盖已有内容。
- 后续快速检查使用记录和目标文件大小，不逐次重读全部文件计算哈希。因此能识别缺失、截断的副本，但不保证发现大小不变的静默损坏。SHA-256 保存在备份记录中，可用于后续独立核验。
- 默认在完整检查成功后，将源图库已删除项目的备份移入 `_deleted`，不永久删除；可通过界面关闭此选项。详见下方删除归档规则。

## 目标目录结构

```text
照片备份/
  2026/10/
    20261027_143025_IMG_1234_a81f29c4d702.HEIC
    20261027_143025_IMG_1234_a81f29c4d702.MOV
    20261027_143025_IMG_1234_a81f29c4d702_edited.JPG
  _versions/2026/10/
    <文件名称>_v<版本时间>_<内容哈希>.JPG
  _undated/
    undated_<原文件名>_<项目短标识>.JPG
  _deleted/<发现删除的时间与批次>/
    2026/10/<原有文件名>.HEIC
  .photo-backup/
    identity.txt
    backup.lock
    <保留的旧版清单>.jsonl
    records-v2/<每次任务的唯一名称>.jsonl
    migration-v2.json
    staging/
```

1.1.0 起，年份、月份及文件名时间均按 `Asia/Shanghai` 时区计算，优先使用 PhotoKit 提供的项目拍摄／创建日期；缺失时归入 `_undated`，不使用备份日期代替。照片原有 EXIF 等内部数据不会改写。记录中的日期按 Foundation JSONEncoder 的参考日期编码（自 2001-01-01 UTC 起的秒数）。备份记录包含原文件名、图库项目标识、文件大小、SHA-256 和日期等信息。

同一项目的原片与实况视频共享原片的文件名主体和项目短标识。编辑结果使用 `_edited` 后缀，调整参数使用 `_adjustment`，编辑基础资源使用 `_editbase`，其他配套资源使用相应角色后缀；均保留实际格式，不把调整参数当作可独立恢复的 Apple 编辑历史。短标识从项目标识生成，默认 12 位，发生冲突时延长，已分配的标识随清单保存。路径冲突时保留已有文件，给新文件增加冲突标识，不覆盖已有内容。过长的文件名按 UTF-8 字节截短，完整原名保存在记录中。

## 从旧结构迁移

启动备份前，应用会检查旧版记录并迁移至平铺结构。也可使用 `Tools/Migrate.swift` 构建的维护工具独立执行迁移，无需访问或下载照片图库。

迁移先写入 `.photo-backup/migration-v2.json`，记录完整的新旧路径、大小和 SHA-256。每次移动前后均校验文件，原有 JSONL 清单保留，新路径写入 `records-v2` 并优先加载；完成的资源继续沿用原有增量键。文件系统移动和记录写入之间中断时，由 `pending-move.json` 在下次打开时恢复。旧目录只用 `rmdir` 清理空文件夹，不递归删除内容。主目录只保留每个资源的当前版本，旧内容保存在 `_versions`。

迁移保持文件总内容不变，原路径与新路径可以从迁移清单核对。迁移后请使用 1.1.0 或更新版本，不再运行旧版应用，否则旧版不能识别新清单。

## 源图库删除后的归档

1.2.0 默认启用“完整检查后，将源图库已删除的项目移入 _deleted 归档目录”。应用读取的是本机系统照片图库，不能直接确认 iCloud 服务器的最新状态：iCloud 删除必须先同步到 Mac，才会被本应用识别；本机从系统图库删除项目也会触发相同处理。

只有完整扫描结束、所有资源处理成功、照片权限仍为完整访问、扫描前后项目集合一致时，才执行删除归档。试运行、中途停止、资源失败或图库发生变化时不处理。空图库、备份项目与当前图库完全不重叠，或一次消失超过 100 个且超过已备份项目的 25% 时，会跳过归档并在日志中提示核对来源和同步状态，避免图库切换或临时异常造成大量移动。

按项目标识判断删除，不按文件名、相簿、资源版本判断。归档涵盖该项目的原片、实况视频、编辑相关资源及 `_versions` 历史副本，保留原有目录关系。每个文件移动前后校验 SHA-256，增量记录同步更新，归档路径及原路径记录保存在清单；删除批次另存 `.photo-backup/deleted-<批次>.json`。发生中断时仍使用 `pending-move.json` 恢复。

如果项目从“最近删除”恢复并以相同图库项目标识重新出现，下次扫描到它时会先把归档资源移回原位置，无需重新下载；有同名冲突时另存，不覆盖其他文件。若重新导入后系统分配了新标识，会作为新项目备份，原归档继续保留。应用不自动清理 `_deleted`，不会永久删除这些内容。

请保留隐藏目录 `.photo-backup`，它用于增量判断和目标身份校验。每次运行独立追加记录，避免大图库反复整体重写索引。复制整个备份目录到新位置时，请一并复制隐藏目录。应用对单一目标加文件锁，但 NAS 对跨机器锁的支持存在差异，不应让多台电脑同时写入同一备份目录。

本机运行日志位于 `~/Library/Application Support/PhotoIncrementalBackup/Logs/`。界面仅保留近期日志，文件保留本次全部错误和结果。大文件正在导出时点击停止，会等当前文件结束；结束后才能正常退出。应用备份期间会阻止因空闲自动睡眠，合盖、断电或强制退出仍可能中断。

## Apple 芯片版 DMG 分享安装包

`dist/照片增量备份-1.4.1-AppleSilicon.dmg` 包含独立构建的 arm64 应用、指向 `/Applications` 的安装入口，以及中文安装说明。要求 macOS 13 或以上版本，不支持 Intel Mac。镜像不包含个人照片、用户偏好、备份清单或运行日志；不会替换当前运行的工作副本。

发行包采用本地临时签名，没有 Developer ID 签名及 Apple 公证。接收者首次打开受到系统拦截时，应确认来源并按镜像内说明，通过“系统设置 → 隐私与安全性 → 仍要打开”允许该应用。若要正式签名、公证发行，需要发行者的 Developer ID 证书和公证凭据。

执行 `bash package-dmg.sh` 可生成图标、编译 arm64 发行副本、构建压缩只读镜像并生成 SHA-256 文件。系统图标转换和磁盘镜像工具可能需要在不受终端沙箱限制的环境运行。每次使用独立暂存目录，且不会覆盖已有同版本镜像。

### 本机开发构建

需要 macOS 13 或以上版本和 Apple Command Line Tools。应用使用本机架构编译，执行本地临时签名，没有开发者公证。

```sh
bash build.sh
bash test.sh
```

测试在独立临时目录中以模拟资源验证增量跳过、记录恢复、图片和配对视频分别记账、同名冲突、文件截断、写入后未记账的恢复、空文件拒绝、残缺记录、任务锁、目标身份和断开挂载路径保护，不修改真实图库。

迁移测试还覆盖上海时区跨月、平铺月份目录、实况资源项目标识、编辑资源命名、无日期资源、已有目标冲突、迁移后增量跳过、重启记录优先级、内容相同复用、内容变化保留历史及移动后未记账的恢复。

可在应用菜单或菜单栏常驻图标菜单中选择“关于照片增量备份”，查看当前安装的版本号和构建号。

1.4.1 起，“只导入新文件”会根据目标 `.camera-import` 中的成功记录识别被整体删除的日期目录，并将日期持久保存在 `excluded-dates.json`，下次不再导入该日期的旧文件或新发现文件；新日期仍正常导入。改名为日期前缀目录不视为删除，仅删除某张照片仍允许重试。关闭开关可主动重导，但不会清除排除日期。此功能依赖保留 `.camera-import`，删除导入记录后无法识别此前删掉的日期。
